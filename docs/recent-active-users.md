# 最近活跃用户

首页在“最新用户”下方显示最近访问社区的 20 位已激活用户，按最近活跃时间倒序排列。

## 接口

`GET /users?order=recentActive&limit=20`

复用用户列表的 `data`、`links` 和分页 `meta`；额外返回 `meta.order: "recentActive"`，供前端确认服务器支持此排序。相同时间按用户 ID 倒序排列，不包含封禁、已删除、未激活或没有活跃记录的用户。

`last_active_at` 仍遵循用户资源的敏感字段规则，对其他用户和访客隐藏。前端只展示头像、昵称和个人主页链接。

## 记录规则

API 中间件在成功响应后记录已认证、已激活且未封禁用户的访问，包括带有效 Bearer token 的公开 API 访问。论坛登录或恢复登录会请求 `/me`，因此也会记录。游客、无效令牌、失败请求不产生记录。

每位用户最多每 5 分钟更新一次，通过条件更新防止并发请求重复写入；不修改 `updated_at`、经验值或触发资料变更事件。此列表表示最近访问过社区的用户，不表示当前实时在线人数。

## 发布

先部署后端，再部署论坛前端。沿用数据库已有的 `users.last_active_at` 字段，本次不需要数据库迁移，也不把注册时间或资料更新时间回填为活跃记录。

如果没有历史记录，列表起初为空，用户登录访问后逐步出现。旧后端不返回 `meta.order`，新版前端会显示可重试的加载失败状态，避免把旧接口的默认排序误当成最近活跃。

## 验证

`php vendor/bin/phpunit tests/Feature/RecentActiveUsersTest.php`

覆盖访问记录、5 分钟节流、排序与分页、隐私字段、账号状态、令牌认证、失败请求，以及经验排行和最新注册排序的兼容性。
